# P2 发票闭环验收 · 2026-11-09

开发模型 GPT-6.1 Sol，High 推理强度。使用本机 Compose 和合成测试数据，从 Next.js 的 3100 端口通过 Java 业务入口验收。

| 项目 | 实测结果 |
| --- | --- |
| P1 数据卷升级 | Flyway V2 在已有 P1 数据卷上启动成功，五个服务健康 |
| 核验与建议 | 初始 F001 缺用途和备注，LangGraph 返回缺项与规则 product-invoice-completeness:1。建议保存后发票和审计尚未变化 |
| 人工确认与回查 | confirmed=false 返回 400。确认后版本从 1 增至 2，独立 GET 与回执一致，两字段复查无缺项 |
| 幂等与并发 | 同键并发请求与随后重放均返回同一回执，目标只增加一个版本和一条审计 |
| 版本冲突 | 两个建议基于同一版本，先确认其中一个，另一建议以新键确认返回 409 |
| 幂等键冲突与回滚 | 同键换建议返回 409。同键用于另一企业发票也返回 409，另一发票及其审计保持原值 |
| 权限与同号隔离 | 匿名读取 401，beta 生成建议与确认均为 403，越租户访问独有企业为 404。甲租户 C002/F001 和乙租户 C001/F001 仍是原值；跨企业提交建议编号为 404 |
| 字段白名单 | 提交金额字段返回 400 |
| 浏览器操作 | Edge 自动化执行登录、查询核验、生成建议、人工确认、独立回查并展开审计，通过 |
| 重启与持久化 | 重启 PostgreSQL 和 Java 后五个服务健康。比较 `verify.py --snapshot` 输出，目标发票、审计以及两张同号对照记录一致 |
| 比赛版回归 | v1.1.0 副本回归 104 项通过，有一条既有 Starlette 弃用提示。源库 SHA-256 与升级前一致 |

本轮验证的是发票闭环，补全内容来自经办人提供的资料。后续规则检索、真实账号权限和流水迁移按各自的验收范围记录。
