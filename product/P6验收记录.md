任务以当前 Cookie 对应账号、租户和企业定位；工具月份由 Java 签发的调用令牌限定。只有 Java 能访问数据库、执行确认。未结束任务唯一索引覆盖 running / waiting_user / blocked，禁止通过换月份新建第二个任务。任务业务状态和单轮轨迹状态分开，一次银行查询成功不会关闭原待办。

并发采用 Redis 所有者短锁（30 秒，每 8 秒续租）及 PostgreSQL active_turn_id/lease_until 双重校验。Redis 释放和续期使用 Lua 比较 turn_id，旧请求无法删除后续请求的锁。创建空任务时锁定企业行解决“还没有任务行”的竞争，数据库唯一索引兜底。业务写入锁顺序为任务→范围→发票，网络和模型调用在事务外。长请求超过原始 TTL 的验收为真实耗时 34 秒，期间再次请求应为 409。

操作账本先记录 pending，再在提案/发票事务内绑定确认结果。任务还有 pending/unknown 时，禁止更正、取消与冲突写入。核实接口锁住任务和发票，按提案及审计事实确定结果；已确认的同键重放返回原 operation_id。proposal 类型账本 confirmed 仅代表建议生成，不能解释成发票已保存。实际保存须有 invoice_audit 和独立回查。

更正目标会使原提案失效，并更新 context_since，防止旧用户输入继续提供新目标的字段。仅更正追问保留目标。提案落生成时的 before_record，跨会话恢复卡片展示原始比较值；发票版本变化仍由确认事务拒绝。

偏好置于 user JSON 的独立 memories 字段，带 memory_id、revision、source_message_id。系统指令限定其只影响表达/默认值；工具白名单、Java 权限、证据与人工确认不接受偏好覆盖。更正或删除偏好后，从历史排除旧来源消息及其同轮助手回声。历史最多八条，预算先裁历史再裁偏好，每项裁剪记轨迹；范围、输入、任务与本轮证据必须保留。强制内容仍超限时明确 incomplete。

敏感字段与实际环境凭据、调用令牌、Cookie 在入库前脱敏。轨迹保留实际模型输入、决策、工具参数/结果、evidence_id、拦截码、上下文字节数和耗时。无效 UUID/JSON 返回通用 400，防止 Spring 默认错误日志回显非法输入中的凭据。原始 HTTP 请求头不进入轨迹。
