后端只有两类加法：GET /api/session，以及 executor.py 的 decision、requirements SSE 事件、tool_result.duration_ms 和持久轨迹 context_budget。现有业务工具、模型策略、表结构、权限、幂等及确认规则未改。原有事件字段保持兼容，原验收脚本未修改。未引入 npm 运行依赖，lock 文件不变；CSS 和系统中文字体不依赖外部资源。

过程数据来源于实际 SSE 与 traces 接口。金额使用 BigInt 整数分格式化，避免浏览器精度丢失。需求只有在成功答案引用了本轮实际证据时标“已核实”，有工具结果本身不等于完整答案。旧轨迹未返回的测量值标“未返回”，不编造耗时或预算。重复工具调用按同名调用序号配对参数。模型原始输入仅在默认折叠的“开发者详情（脱敏）”内。

并发/保存保护沿用 P6：X-Chat-Scope、稳定 Idempotency-Key、恢复绑定、企业月份范围、未知操作和回查一致性。前端额外将“保存结果待核实”作为独立禁用条件，不能因刷新失败重新开放确认。已保存但回查断网时，按真实审计找到 operation_id，调用 reconcile 并独立读取发票；没有明确事实时保持待核实。

范围切换清空旧任务、建议、恢复状态、偏好来源/审计、轨迹引用及旧保存反馈，刷新失败也不展示为新企业的可写建议。选择不同月份时展示原任务与原建议，同时写明不能确认。浏览器确认后，原任务按后端事实结束，回执留在消息流。

## 设计与评审

使用 frontend-workbench 技能。按用户指定三栏结构和 #002FA7 主色实施一次现有工作台升级，没有另设三个候选设计或阻塞用户选版。视觉层级：任务范围为窄侧栏，对话占主要宽度，证据与建议常驻右侧；窄屏使用普通可按 Tab 操作的视图按钮组，避免不完整的 ARIA tab 模式。

进行了不继承历史的只读独立代码评审，限指定前端四文件。评审不作为截图或交互通过依据。已修正其指出的旧范围残留、未知结果重复确认、同名工具参数误配、旧企业反馈残留、视图按钮语义、未知字节显示为零，以及固定顶栏高度风险。主代理结合真实浏览器检查并定向复核；没有宣称独立视觉评审通过。

主要正文/次要文字/主操作/警示/成功标签的实测对比度分别 15.74、6.28、10.69、7.30、6.56，均高于普通文字 4.5:1；输入边界 #8290a6 与白底为 3.24:1，焦点颜色另按 3:1 下限检查。证据 data/p7-main-validation/contrast.json。此为主要颜色角色及实际键盘检查，不代替完整的辅助技术合规认证。

## 限制

- 模型状态初始为“待验证”。对话被接受后只能确认配置存在，不能说明模型输出正确；503 更新为未配置。没有通过新增接口暴露模型配置。
- 本步未执行可选 Qwen3 8B --live，也未新增该可选参数；P6 真实模型未通过项仍有效。真实模型全量复验与动作稳定性修复属于下一步。
- 完成任务的全历史列表不在现有 API 中，刷新仅恢复未结束任务的最近消息；已结束任务的完整轨迹仍需持有其 task_id。没有伪造历史入口。
- 浏览器测试使用 Windows 本机 Edge 和已信任 CA，Linux 或未安装 Edge 的环境需自行准备匹配浏览器；不忽略证书错误。
- 原始 JSON 保留为默认折叠的复核入口；本轮没有新增 Markdown 渲染依赖，回答按安全纯文本显示。
- 这些截图和测试是合成数据与替身模型结果，不代表赛事统一模型验收或真实财税业务生产验收。
