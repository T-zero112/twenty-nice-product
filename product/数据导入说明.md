## 运行

在隔离实例的源码副本根目录执行（不要指向 3443 主工作台）：

```powershell
$env:COMPOSE_PROJECT_NAME = 'tax-product-p8'
# 先重建 business 镜像，带上 Rules.selection 改动
docker compose -f product/compose.yaml -f product/compose.https.yaml -f product/compose.external-acceptance.yaml build business
docker compose -f product/compose.yaml -f product/compose.https.yaml -f product/compose.external-acceptance.yaml up -d --no-deps --wait business
python product/import_contest_data.py --project tax-product-p8
# 只核对、不写入：
python product/import_contest_data.py --project tax-product-p8 --check-only
# 默认读取随产品附带的 product/data/contest/02_示例数据.xlsx；如需用其他副本，加 --xlsx "<路径>\02_示例数据.xlsx"
# 接口核对（权限、规则版本）；加 --chat 会额外发起一次真实模型对话
$env:PRODUCT_TEST_BASE = 'https://localhost:13451'
$env:SSL_CERT_FILE = (Resolve-Path product/tls/local/ca.crt).Path
python product/verify_contest.py --chat
# 离线单测（默认比对附带的官方工作簿，也可用 CONTEST_XLSX 指向其他副本）
python -m unittest product/test_import_contest_data.py -v
```

- 项目名不以 `tax-product-p8` 开头时，脚本拒绝写入。写主工作台必须显式加 `--allow-main`，并且要先重建主工作台的 business 镜像。
- 脚本可重复运行：只补缺失行（ON CONFLICT DO NOTHING），不会覆盖已经修改过的用途和备注。
- 从 `PRODUCT_P8_INITIAL_DUMP` 恢复数据库后，contest 数据会消失，需要重新运行导入。

## 金额门槛（V9，2026-11-12 补做）

- Flyway `V9__rule_amount_threshold.sql` 给 `invoice_rule` 增加可空列 `min_amount_cents`。
  - 规则的 `required_fields` 只对 `amount_cents >= min_amount_cents` 的发票生效，等于门槛也算在内。
  - 列为空时与原来一样，所有发票都要求。
  - 发票金额未知时按要求处理，偏保守。
- 门槛依据 03_业务规则.docx 中 R003 1.0 原文：「单张发票金额大于或等于 1000.00 元时必须填写用途，等于 1000 元也在范围内」，所以取 100000 分（≥）。
  - 已停用的 R002 1.0 也按原文写入 100000，只作版本留档，不参与选规。
  - R002 2.0 没有门槛，甲企业不受影响。
- Java 端：`Rules.requiredFor(rule, amount)` 先按门槛算出这张发票的必填字段，再交给 Agent 的 invoice-review。check_purpose、生成提案时的核验，以及 review 接口都走这条路径。Agent 镜像不需要改。
- 导入脚本对规则行使用 `ON CONFLICT ... DO UPDATE SET min_amount_cents`。V9 之前已经导入的库，重跑一次脚本就能补上门槛；规则的其他列不改。
- 必须先重建 business（Flyway 升到 V9），再运行导入脚本。

## 启动时自动导入（start.ps1 / start.sh）

- `product/start.ps1 -Https`（Windows）和 `product/start.sh`（Linux/macOS，默认 HTTPS，`--http` 只开 HTTP）在服务全部 healthy 之后，自动导入赛题数据，步骤如下：
  1. 先运行 `--check-only` 核对。
  2. 如果数据缺失或不完整，执行导入：只补缺失的行，不会覆盖已经修改过的用途和备注。
  3. 导入后再核对一次。
  4. 成功时最后一行输出 `赛题数据就绪：40 张发票、48 条流水`；失败时给出明确错误，并以非零退出。
- 跳过自动导入：`start.ps1 -SkipContestImport` 或 `start.sh --skip-contest-import`。
- 导入脚本在 importer 镜像里运行，主机只需要 Docker，不需要 Python：
  - 镜像里有 Python 3.12、openpyxl，这次新增了 `psycopg[binary]==3.2.10`。
  - 运行方式是 `docker compose run --rm --no-deps -T -v <product>:/work --entrypoint python importer /work/import_contest_data.py --direct-db --allow-main`。
  - `--direct-db` 从挂载的 `.env` 读取 `PRODUCT_DB_PASSWORD`，直接连接 compose 服务 `db`。
  - start.sh 额外传 `--user $(id -u):$(id -g)`，保证脚本能把新密码追加进 `.env`。
- `--allow-main` 只由启动脚本传入，因为这是使用者在明确启动自己的实例。手动运行导入脚本时，原有的「非 tax-product-p8 项目拒绝写入」保护不变。
- `PRODUCT_U001_PASSWORD`、`PRODUCT_U002_PASSWORD` 不存在时，由导入脚本生成并追加到 `product/.env`，不会打印出来。
- `start.sh` 生成证书的方式与 `tls/generate-local.ps1` 相同：本地 CA 365 天，localhost 服务器证书 90 天，需要 openssl 1.1.1 及以上。`product/.gitattributes` 规定 `*.sh` 使用 LF 换行。
- 项目名和端口沿用原有的环境变量覆盖方式（`COMPOSE_PROJECT_NAME`、`PRODUCT_HTTP_PORT`、`PRODUCT_HTTPS_PORT`、`PRODUCT_IMPORTER_IMAGE`），主工作台的默认行为不变。
